# ASO-исследование Google Play

Используй для органического позиционирования Android-приложения, а не как инструкцию по покупке рекламы.

## Контекст продукта

Сначала найди в материалах или уточни отсутствующие факты: package name/ссылку, реальные функции, аудиторию, бесплатные и платные возможности, рынки и языки. Данные одной страны не подменяют данные другой. Для нового приложения package name может быть еще не выбран: исследование этим не блокируется.

Прочитай [принципы](references/knowledge/play-foundations.md) и [методику запросов](references/knowledge/play-keyword-research.md). Для текста карточки используй [поля и правила](references/knowledge/play-metadata.md).

## Исследование

- Подбери конкурентов по пользовательскому сценарию и проверь их реальные листинги. Для каждого зафиксируй URL, рынок, язык, дату, доступные функции и позиционирование. Наблюдение из стора — не доказательство дохода или числа активных пользователей.
- Собери фразы из описания продукта, релевантных конкурентов, отзывов, наблюдаемой выдачи и предоставленных ASO-экспортов. Запиши источник каждого запроса. Официального универсального Play Search Popularity 0–100 этот набор не предоставляет; не придумывай показатель.
- Разметь релевантность 0–3 по подтвержденным функциям: 0 — исключить; 1 — смежный сценарий; 2 — полезная функция; 3 — основной сценарий. Это редакционная оценка, не расчет Google.
- Если работаешь с CSV, колонки: `query,locale,country,source,relevance,volume,volume_source,note`. Неизвестный volume оставляй пустым; измеренный volume требует источника и единиц/периода в note.

```bash
python3 <путь-скилла>/references/shared/cli.py keywords research/keywords.csv --output research/keyword-bank.json
```

Команда сортирует по указанной релевантности, не собирает данные из Play и не сравнивает volume разных провайдеров как одну шкалу.
Keyword bank сохраняет также отклоненные варианты с `decision: excluded`: они нужны для истории исследования. В рабочий shortlist и итоговые метаданные не включай relevance=0.

## Результат

Подготовь для каждой локали несколько естественных вариантов title/shortDescription, затем fullDescription выбранного варианта. Не переноси iOS subtitle, keyword field или правило запрета любого повтора между полями. Используй подтвержденные функции и честные условия монетизации.

Сохрани JSON вида `{"en-US":{"title":"…","shortDescription":"…","fullDescription":"…"}}` отдельно от keyword bank, проверь:

```bash
python3 <путь-скилла>/references/shared/cli.py validate metadata/listings.json
```

Передай конкурентную таблицу с источниками, keyword bank, варианты текста, валидированный JSON и список пробелов в данных. Наблюдаемые позиции требуют страны, языка, времени, устройства/метода и глубины выдачи; не выдавай выборочную проверку за стабильный глобальный ранг.
