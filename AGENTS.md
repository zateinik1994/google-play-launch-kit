## Общие рабочие правила

- Сначала используй известные факты о продукте. Запроси лишь отсутствующие сведения, которые меняют результат: аудитория, функции, монетизация, рынки/языки, package name для live-операций. Не выдумывай платные или бесплатные функции.
- Правила Google меняются. База знаний указывает source/date; перед live запуском проверяй применимые официальные страницы и реальное состояние Console.
- Нет iOS keyword field, subtitle или Apple Search Popularity в Google Play. Не обещай вычислить секретную формулу ранжирования; разделяй измерение, редакционную оценку и гипотезу.
- Для графики показывай реальные экраны пользователя и правдивые сценарии. Технический validator не заменяет визуальную проверку и policy review.
- Offline-проверка, remote validateOnly, commit, появление карточки и включение рекламы — разные состояния. Назови фактическое состояние результата.
- Пользуйся уже данным разрешением на конкретные live-операции. Подготовка файлов не разрешает commit, публикацию в GitHub или рекламный расход. Когда разрешения на внешнее изменение нет, сначала подготовь reviewable файл/diff/план, затем уточни его. Не требуй повторного согласования уже разрешенного действия.
- Не запрашивай секреты в чате. Храни credentials вне клона; пользуйся ADC/environment. Не повторяй операции с неизвестным исходом без проверки состояния сервера.
- Отчет по одному источнику/выборке не считается полным исследованием. Указывай происхождение, дату, страну/язык, контекст измерения и существенные пробелы.

## Пути и структура

`knowledge/`, `shared/`, `docs/` — канонические общие материалы. `skills/*/references/` ссылаются на них относительными симлинками, чтобы скилл работал из клона и после установки. `install.sh --copy` раскрывает ссылки для отдельной переносимой копии. Команды из скилла используют путь самого скилла и не предполагают `~/.claude` или `~/.codex`.

Результаты приложения размещай в выбранной пользователем папке, например `workspace/<app>/`; не подменяй учебные данные `examples/data/` реальной клиентской информацией. Экспорты `output/` и `outputs/`, workspace и credentials исключены из Git.

## Если изменяешь инструментарий

Не копируй knowledge или shared в каждый скилл. Обновляй canonical файл; новые reference links делай относительными. Проверяй фактическое поведение измененного CLI и значимые invariants (API порядок, ошибочный ввод, backup до записи, отсутствие live вызовов у dry run). Новые API capabilities должны иметь реальную реализацию и честно описанные ограничения.

```bash
python3 -m unittest discover -s tests -v
python3 scripts/check_knowledge.py
```

Правки генератора проверяй в браузере: загрузка реального файла, редактирование, locale round trip и экспорт PNG нужного размера/цветового формата. Не выполняй live действия для тестирования без отдельного разрешения. Заверши кратким результатом, проверками и существенными ограничениями.
